# P0 技術驗證清單

目標：在**公司 Windows 11 電腦**上確認 DESIGN.md 的技術假設都成立，再進入 P1。
以下所有指令都在 repo 根目錄、PowerShell 中執行。

## 0. 準備

```powershell
# 安裝 uv（若公司網路不允許，改由內部管道取得 uv.exe）
uv sync
uv run pytest -q          # 單元測試應全部通過
```

> 若 `uv sync` 需透過內部 PyPI mirror，先設定 `$env:UV_INDEX_URL = "<mirror 網址>"`。

## 2. Bitbucket Server API

先在 Bitbucket 建立一個**測試用** catalog repo，把 `examples\catalog` 的內容推上去，並用 Git LFS 加入至少一個 zip，例如：

```powershell
git lfs track "tools/*/releases/*/*.zip"
# 放一個任意 zip 到 tools\register-viewer\releases\1.1.0\register-viewer-1.1.0.zip
```

接著執行（腳本為唯讀，不會寫入伺服器）：

```powershell
$env:TOOLMANAGER_TOKEN = "<個人 HTTP access token>"
uv run python scripts\p0_check_bitbucket.py --url https://<bitbucket 網址> `
    --project <PROJECT> --repo <catalog repo> `
    --artifact tools/register-viewer/releases/1.1.0/register-viewer-1.1.0.zip
```

| # | 檢查項目 | 若失敗的備案 |
|---|---|---|
| 2.1 | REST commits API 取得最新 revision、取得使用者名稱 | 確認 token 權限（需 repo read） |
| 2.2 | archive API 下載 catalog zip | 改用 REST browse API 逐檔下載 |
| 2.3 | archive 中 LFS 檔案維持為指標檔（不含實際內容） | 改用 archive API 的 `path` 參數只抓 manifest 相關路徑 |
| 2.4 | catalog 解析成功 | 修正 manifest |
| 2.5 | raw + LFS batch API 下載並通過 sha256 驗證 | 確認 LFS 是否啟用；改用 Bearer 認證 |

另外請記下 Bitbucket 頁尾顯示的**版本號**。

> 發布用的「REST API 建立 commit」需要寫入權限，會在 P3 前另外以測試 repo 驗證。

## 2b. Jira（回報問題）

在瀏覽器（已登入 Jira）開啟以下網址，取得 `catalog.toml` 的 `[jira]` 需要的數字 ID：

| 項目 | 網址 | 取用欄位 |
|---|---|---|
| `project_id` | `https://<jira>/rest/api/2/project/<PROJECT_KEY>` | `"id"` |
| `issue_type_id` | `https://<jira>/rest/api/2/project/<PROJECT_KEY>`（同一頁的 `issueTypes`） | Bug 那一項的 `"id"` |

填入後在 ToolManager 點「回報新問題」，確認 Jira 建單頁的專案、類型、label（`tm-<工具 id>`）與描述都已預先填好；「查看已知問題」能列出該 label 的 ticket。
